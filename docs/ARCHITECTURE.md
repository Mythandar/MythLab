# Architecture

## Scope and environment
Milestones A-E provide Windows inventory, LAN discovery, live status, Wake-on-LAN, integrated SSH and external connections. Wake & Connect remains Milestone F, pending independent E review. Inspected 2026-09-19: Windows 11 x64 (10.0.26200), .NET SDK 10.0.400, Windows Desktop runtime 10.0.11, Git 2.55. No extra workloads required for WPF. No inherited AGENTS.md found. The project is hosted at https://github.com/Mythandar/MythLab.

## Structure and dependencies
- App: net10.0-windows WPF, MVVM with CommunityToolkit.Mvvm, built-in WPF Fluent theme. No browser-based app shell.
- Core: domain records, validation and small service contracts; no WPF, database or native networking dependency.
- Infrastructure: Microsoft.Data.Sqlite, explicit SQL and numbered schema migrations. No ORM: the initial model is small and migrations remain reviewable.
- App composition: Microsoft.Extensions.DependencyInjection, Microsoft.Extensions.Logging via Serilog and rolling JSON file sink. No generic host needed until hosted background work exists.
- Separate Core and Infrastructure test projects use xUnit and Microsoft.NET.Test.Sdk. Tests require no Internet or LAN access; one TCP status test uses loopback only. Wake tests never send real packets.
- Exact dependency versions and licenses: THIRD-PARTY-NOTICES.md and NuGet lock files.

## Naming
build/Identity.props is the authoritative location for the MythLab display name and executable assembly name. It supplies executable version resources and generated AppIdentity constants. The solution, project folders and namespaces use MythLab. AppDataId deliberately remains Homelab.RemoteManager: it locates the pre-portable inventory for one-time import and must not change without a migration. The active portable Data folder is beside the executable and does not depend on this ID. No installer, logo or splash screen exists yet; an eventual installer must import Identity.props.

## Domain and persistence
Device has a GUID independent of address, descriptive metadata, last observation, status-check configuration and unverified/verified WoL settings. ConnectionProfile has its own GUID and device foreign key; many profiles can belong to one device. CredentialReference is separate reusable metadata; profile rows reference its GUID. No secret-bearing property exists in serializable models. Authentication type and private-key path belong to credential metadata; saved passwords/passphrases live only in Windows Credential Manager.

SQLite, settings and logs live in Data beside the executable (AppContext.BaseDirectory). The stable application ID is retained to locate pre-portable AppData for one-time migration and future credential target naming. See PORTABLE.md for publishing, migration and secure-secret portability boundaries. Tables separate devices, credentials and profiles; profile foreign keys cascade with device deletion and restrict deletion of referenced credentials. Device bodies are versioned JSON inside SQLite alongside normalized lookup columns. This keeps early configuration flexible without combining device/profile/credential identity; introduce typed columns in migrations when queries justify them. IP is a duplicate warning signal, never identity. Matching prioritizes normalized MAC, case-insensitive hostname and then current IP. Saving rejects any match to another device so DHCP collisions require deliberate editing, not accidental merging.

Repository operations run on worker threads behind a semaphore; Microsoft.Data.Sqlite async methods are synchronous, so merely awaiting them would still block WPF. Use WAL, parameters, transactions and a short busy timeout. Cancellation is honored while queued and before commit; an already committed operation remains committed. Migrations reject newer schemas, never silently overwrite them. Normal settings use atomic JSON replacement and validation. Unknown/broken settings are reported, not silently discarded.

## UI and lifetime
Shell uses navigation and device cards, with a dedicated modal editor for Add/Edit. Validation stays in Core and is displayed in the editor. Delete requires a UI confirmation. Async commands disable overlapping mutations. App startup awaits database initialization and initial load; fatal startup failure produces a safe error and exits. No passwords or raw exception messages are included in structured logs. Disk logs roll daily/at 5 MB and retain at most seven files. Diagnostics displays bounded recent operational entries. Cards begin Unknown until the first live check. Future screens are clearly labeled as upcoming.

## Discovery (Milestone B)
Enumerate active IPv4 unicast interfaces and actual masks. Permit interface selection. Bound scan concurrency, constrain large ranges and allow explicit ranges rather than silently sweeping a /8. Merge ICMP, GetIpNetTable IPv4 neighbor information and local SendARP evidence, then bounded reverse DNS. ICMP failure must not exclude a neighbor. Native calls run away from UI with bounded work; cancellation stops scheduling, even where a native call cannot be interrupted. Record when the scan read evidence separately from a live ping/local-interface observation. A neighbor-cache read provides no remote last-alive time and never proves Online. Skip direct SendARP when a usable selected-interface cache MAC already exists; still ping to check availability. OUI provider is optional and must work offline. No elevation should be required for ordinary read-only discovery; document unsupported/restricted calls. Never infer WoL support from discovery.

## WoL and monitoring (Milestone C)
The application constructs a 102-byte magic packet (six FF bytes and sixteen target-MAC copies) and sends UDP internally, bound to the chosen local IPv4 address. Automatic routing uses the actual subnet mask and target IP; multiple matching adapters require selection. An unavailable saved interface fails clearly. Explicit destinations must be a local directed broadcast or 255.255.255.255; /31 and /32 are not broadcast networks. Remote-subnet relays remain deferred. The editor lists active interfaces and preserves missing saved selections.

Defaults are three packets, 250 ms apart, one additional burst after 1000 ms, UDP port 9. Packet count, retries and both delays are configurable. Wake and Test Wake check availability first, avoid sending to an already-online target, send packets, then observe until success, cancellation or timeout (120 seconds after sending; poll every three seconds by default). Both actions perform the same safe observation; Test Wake labels diagnostic progress explicitly. Already-online or initially-Unknown devices cannot newly qualify as Verified. Only an Offline → packets sent → Online observation verifies unchanged configuration; this is observational evidence, not proof of causation. Sending alone never marks Online.

DeviceActivityViewModel coordinates per-card operations and at most eight concurrent status probes, waiting the configured interval (30 seconds default) after each sweep. No overlapping sweeps; waking cards are excluded. Check now is available. Status resolves the preferred hostname on every check, otherwise uses the saved IP. It tries distinct resolved IPv4 addresses within one DNS-plus-ICMP/TCP budget, reserving time for later addresses. It does not fall back to a possibly stale saved IP after DNS failure. Offline means the configured check failed, not proof of power-off; failed resolution/unsupported checks are Unknown. Wake routing uses the saved IP when present; update stale IP/subnet information or explicitly select the correct interface.

Cards start Unknown until checked; last-seen timestamps are preserved. Waking is transient. Atomic repository observation updates merge only status fields into the current device, compare endpoint/configuration and timestamps, never insert deleted records, and cannot overwrite edits or verify changed wake settings. Stale editor saves preserve current observations; changed targets invalidate status/verification. Per-card generation checks discard stale UI completions. Closing cancels and drains discovery, status and wake work before disposing persistence. Ordinary UDP, ICMP/TCP and interface enumeration require no administrator privileges; local firewall policies and hardware configuration can still prevent success.

Core contains packet/routing logic and contracts; Infrastructure contains Windows status, UDP transport and the wake-observation workflow; App contains UI coordination. These small boundaries support fake networking in tests and later Wake & Connect without coupling wake to a launcher. There are no new dependencies. Settings, observations and logs remain under portable Data; no secret fields or storage paths change.

## SSH decision record (Milestone D)
Selected: SSH.NET -> ShellStream -> bounded terminal bridge -> locally bundled xterm.js in WebView2. SSH.NET supplies password/key auth and host-key events; ShellStream supplies a PTY but is not a terminal emulator. Plain WPF TextBox rendering is inadequate for full-screen terminal apps. Alternatives: native third-party terminal controls bring licensing/maintenance lock-in; external OpenSSH does not provide the required saved-password integrated experience; ConPTY applies to local sessions and does not replace SSH transport.

The original spike checklist covered: UTF-8 chunk boundaries, ANSI/vim/top behavior, input/resize, copy/paste, reconnect/disposal, simultaneous streams, throughput/backpressure, keyboard/IME/accessibility and WebView2 DPI/airspace behavior. Keep a small session boundary (input, output, resize, close) usable by future ConPTY sessions; do not invent a plugin framework.

Security gate: package assets locally with license copies; never load a CDN. WebView2 needs an installed Evergreen runtime or documented installer bootstrap; fixed runtime increases deployment size and patch responsibility. Restrict virtual host/content origin, navigation, new windows, downloads and permissions. Enforce CSP and validate origin/type/size of every bridge message. No generic host-object exposure, eval of remote text, or arbitrary URL handlers. Treat terminal output and clipboard escape sequences as hostile. Never log input/output because users may type secrets. Disable automatic clipboard writes.

Known hosts must key by normalized host + port, key algorithm and SHA-256 fingerprint/public key. Unknown keys require an explicit fingerprint trust decision before authentication; changed keys fail closed and require deliberate replacement. Do not offer an invisible accept-all mode. Credential Manager targets use stable GUID references; secrets are fetched only for authentication, never displayed back to UI. Cleanup is best effort for managed memory; do not promise zero plaintext in process memory.

## External connections (Milestone E)
ConnectionProfile metadata passes through Core ExternalConnections validation/building and ExternalConnectionService into IConnectionLauncher. Infrastructure supplies WindowsExecutableLocator and WindowsConnectionLauncher. The existing IDeviceStatusService performs optional TCP readiness checks; no second network stack or plugin framework was introduced. Native process launch and executable discovery have fakeable boundaries.

Native requests hold an executable path and an argument list. ProcessStartInfo.ArgumentList preserves spaces, quotes and malicious-looking substituted values as individual arguments; UseShellExecute is false for native executables. There is no cmd /c or PowerShell command-string expansion. Allowlisted substitutions are {ip}, {host}, {hostname}, {port}, evaluated once without recursive replacement. Executable paths never contain placeholders; .exe paths must be explicit, absolute or relative to the application directory. Known shell interpreters are refused for custom profiles. The restricted local-terminal type opens PowerShell, pwsh or Windows Terminal interactively with fixed arguments and no device-derived commands. Explicit custom executables remain trusted user configuration: the called program controls the interpretation of its own arguments.

HTTP/HTTPS URIs are the sole shell-dispatched launch type (the Windows default browser). URI construction escapes substituted values and rejects other schemes and userinfo. External profiles cannot reference MythLab credentials and have no dependency on ICredentialStore. Secret placeholders and common authentication command-line options are rejected. Configuration fields are non-secret metadata, not a vault: never paste passwords, tokens or passphrases into arbitrary names, URLs or arguments. Validation cannot identify every possible literal secret in free text. No argument values, executable paths or URLs are logged; structured launch events record profile ID/type and safe failure categories.

RDP is an external fallback using the system mstsc.exe, /v:host:port (default 3389), fullscreen or a 1280x720 window request. Windows manages its authentication independently; no .rdp files or password forwarding. RealVNC uses explicit host::port (default 5900). Moonlight uses stream, host and a separately quoted app name when configured; with no app name it opens Moonlight's native host/app picker. Host pairing remains in Moonlight. Neither viewer is bundled.

SQLite continues to store portable profile JSON and nullable credential references in the existing table. Rdp is appended to ConnectionKind so previous numeric values remain stable; RdpFullscreen defaults false for old JSON. No schema migration or dependency change. Missing executables do not prevent saving or preserving a profile. Explicit paths take precedence; blank RealVNC/Moonlight paths probe several conventional per-user/Program Files locations, and blank Terminal uses Windows PowerShell. RDP always uses the Windows system client. Availability is recomputed on loading/launching, never stored. File-system probes run off the UI thread. A copied folder retains definitions and can update the executable path under the same profile ID.

Optional ReadinessPort performs one TCP check against the device hostname/IP with the profile's finite timeout, using the existing multi-address DNS/check budget. Blank means launch immediately. This does not wake, retry until a machine boots, or mark WoL verified. Cancellation is available on My Devices and Connections; it prevents launch before handoff. Once handed to Windows, the external application's lifetime is independent of MythLab. TCP readiness proves only a listening service, not successful authentication or protocol compatibility. For URLs on a different endpoint, leave the device readiness check disabled.

SSH remains directly accessible on every card. Configured external types add one primary action each and use a chooser for multiple profiles of that type. More contains Add connection and contextual Edit external connections; that chooser permits editing any external type. Profile deletion remains in Connections with confirmation. All buttons wrap in the existing responsive layout, with keyboard/automation properties retained. Profile fields in the editor are shown by type; one argument per line preserves boundaries without a command-line parser.

Milestone F remains unimplemented pending independent E review. It will orchestrate wake, host/service waits and connection handoff using these existing boundaries.

CLI references: [Windows mstsc](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/mstsc), [RealVNC address/port syntax](https://help.realvnc.com/hc/en-us/articles/360002321357-Why-can-t-I-connect), [Moonlight command-line parser](https://github.com/moonlight-stream/moonlight-qt/blob/master/app/cli/commandlineparser.cpp).

## Portable data / secure secrets — binding v0.1 decision
Portable Data is the default architecture. All inventory, device and connection definitions, usernames/non-secret metadata, credential references, WoL configuration, MAC/IP/hostname, groups/tags/notes and settings stay in Data. SSH trust records use Data/ssh/known-hosts.json; logs use Data/logs; a future terminal uses Data/WebView2 for browser user data/cache. AppPaths owns these paths. Startup actively probes Data and logs for write access and reports failures without an AppData fallback.
Secrets remain exclusively in Windows Credential Manager. A copied folder can have valid profiles with missing local credentials. Milestone D must show Missing credential and recreate the secret under the same GUID reference, preserving every device/profile. It must distinguish missing from access denied/store errors and must never fall back to plaintext SQLite/JSON. No portable encrypted vault in v0.1. See DATA-SECURITY.md for the full policy and acceptance gates.
WebView2 is lazy and terminal-only: prefer installed Evergreen, do not bundle Fixed Version by default, detect missing runtime before terminal creation and provide a useful terminal diagnostic. Explicitly select AppPaths.WebView2UserData and check writability. Non-terminal features must run without any WebView2 runtime. No WebView2 dependency is introduced in Milestone B; detection/creation tests belong to the terminal spike.

## Discovery implementation decision (Milestone B)
Core owns IPv4 subnet/range rules and discovery evidence models. Infrastructure owns the bounded scan engine and ILanProbe Windows implementation. GetIpNetTable suffices for IPv4; native row/table layouts use Marshal offsets and strides. Cache data is evidence only, never proof of Online. Ping/DNS use async cancellation; SendARP has a process-wide eight-call cap retained until native calls return. Scan ranges are explicitly limited to 4096 addresses on the selected subnet. Interface availability is rechecked, and IPv6-only/disappearing interfaces are skipped. See DISCOVERY.md for routing, cache-freshness and timeout limitations.
The Discovery view model streams rows, tracks managed matches, opens the normal editor with discovered fields, and leaves WoL Disabled by default. The main window cancels and drains discovery before disposing shared services. No terminal/browser environment is initialized for discovery. Microsoft.Extensions.Logging.Abstractions is now referenced by Infrastructure for structured network diagnostics (MIT; already a resolved dependency).

## Milestone D implementation (2026-09-26)
The renderer spike established the SSH.NET / ShellStream / ITerminalSession / xterm.js / WebView2 path. The session contract is limited to read, write, resize and asynchronous disposal; a future ConPTY session can use it without changing credential or device models. SSH.NET 2026.0.0 (MIT), its BouncyCastle.Cryptography 2.7.0 dependency (MIT), Microsoft.Web.WebView2 1.0.4191.47 (Microsoft BSD-3-Clause license in the selected SDK package), xterm.js 6.0.0 and fit addon 0.11.0 (MIT) are pinned. See THIRD-PARTY-NOTICES.md for local asset provenance and licenses.

SqliteDeviceRepository also implements IConnectionRepository using the existing profile/credential tables and serialized worker-thread access. WindowsCredentialStore wraps generic CredReadW/CredWriteW/CredDeleteW entries scoped to the current user/machine. Availability checks do not materialize the secret. Stored secrets are read for authentication or in-memory compensating updates; password editors always start empty. Delete protection preserves referenced credentials; failed Windows deletion restores metadata so cleanup can be retried. Windows and SQLite cannot share an atomic transaction: a process crash between operations can leave an orphan Windows entry, but never a plaintext fallback. KnownHostsStore validates records and atomically replaces Data/ssh/known-hosts.json, rejecting changed identities.

TerminalWindow initializes Evergreen only on demand, checks writable Data/WebView2, and serves embedded resource assets from a restricted local HTTPS origin. No Internet-hosted script or Fixed Version runtime is used. It disables host objects, browser password saving/autofill, permissions, downloads and external navigation. CSP and native origin/type/size checks constrain the bridge. OSC 52 clipboard access is disabled. Authentication never crosses the bridge; terminal input/output is never logged. Output has a bounded native queue and one acknowledged browser chunk at a time; input is bounded too. Output saturation applies transport backpressure, rather than disconnecting. Input overflow, renderer failure or a visible renderer that stops acknowledging output still terminates the session. Reconnect, close and application shutdown cancel/drain session work and dispose the browser.

The first release uses separate terminal windows, permitting concurrent sessions. Tab management remains deferred. A missing runtime or unwritable browser cache affects terminals only. Ordinary networking and Credential Manager use require no elevation. Browser/runtime servicing is Evergreen's responsibility; shipped managed/native dependencies require an application update.

Validation passed for Windows native credentials, password and encrypted-key SSH against a disposable loopback server, trust/reject/changed-key handling, ANSI/split UTF-8, resize, reconnect, CSP and the single-file deployment mechanism. This is a functional first terminal, not a claim of complete terminal compatibility: manual vim/top, IME, accessibility, DPI and long-running throughput acceptance remain open. Multi-process editing of known-host records is not coordinated; close other instances before editing trust or backing up portable data.

## Focused Milestone D consistency review
CredentialSaveService (Core) coordinates the two independent stores; the WPF editor only collects input and displays its safe result. Before a secret mutation it snapshots current metadata and the previous Windows secret in memory, failing before mutation if that secret cannot be read. New IDs with an unexpected existing Windows secret are rejected. Authentication-type changes replace or remove the old secret rather than reinterpreting it under new metadata.

Updates write the secret first, then metadata. A throwing operation is treated as potentially committed. On failure, compensating actions restore the old secret (or delete a newly created one) and restore previous metadata (or remove a new row). Both restorations are attempted independently. Rollback uses no cancelled caller token, and failures produce an explicit manual-repair warning without retaining provider exception messages. Once mutations begin they run to completion/compensation; closing does not interrupt a write. Metadata-only changes do not read or rewrite the secret.

This is NOT a distributed transaction. Snapshots are memory-only and are not crash-recovery journals. Process termination, power loss, rollback failure, or concurrent edits by another instance can leave inconsistent state requiring manual repair. The service serializes its own saves, not operations in other processes. No secret is persisted to SQLite/JSON/logs/temp files or sent to the UI/command line. Managed strings cannot promise deterministic zeroization.

A requested main-window close is remembered while metadata work is busy, prevents new main-window actions, and resumes automatically when the work finishes, then drains sessions/discovery/monitoring normally. If an editor reports a save/repair error, the user can review it before dismissing that editor.

Failed WebView2 initialization marks that terminal unusable: Reconnect is disabled with an explicit close/reopen diagnostic. A fresh terminal creates a fresh browser after the runtime/path problem is corrected. Renderer-process failures use the same behavior. SSH connection/authentication failures with a healthy renderer remain reconnectable. Existing browser security restrictions and bounded queues are unchanged.

## Focused D/E review before F (2026-09-27)
SshTerminalSession retains a 64-chunk, 8-KiB output queue using awaited bounded writes. SSH.NET 2026.0.0 invokes ShellStream.DataReceived synchronously on its receive worker and its own read buffer can grow. Therefore simply pausing an asynchronous reader would move the unbounded backlog into the library. The receive callback drains chunks and waits for queue capacity on that background worker; it never blocks the WPF thread or dispatches an unbounded set of producer tasks. This also stalls further transport receives/window progress. Bytes are neither decoded nor reordered in this layer. The initial drain runs on a worker too. The queue's payload is capped at 512 KiB, plus the pending consumer/producer chunks and SSH.NET/OS transport buffers; this is not a claim that all process memory is limited to 512 KiB.

Cancellation completes the queue and releases a blocked producer before SSH disposal. A full queue is not an error. Transport errors still propagate; renderer failure cancels the session. One chunk remains in flight to WebView2. The old 15-second acknowledgement limit is replaced by a two-minute *visible-time* watchdog. Minimized/hidden time is excluded to tolerate Chromium throttling; while hidden, unacknowledged output remains bounded and the transport can be backpressured. A crashed renderer is handled immediately by ProcessFailed; an unresponsive but uncrashed hidden renderer remains paused until shown, when the finite watchdog resumes. Disconnect/close cancels at any time. Input/output is never logged.

An unknown host key now ends the first, untrusted SSH attempt before authentication. The connection and its deadline are disposed before the human trust decision. Approval triggers a new timed connection that must present exactly the approved identity, even if the known-host file changed in between. Changed keys fail closed; an approval is memory-only until successful authentication, after which trust is recorded normally. Each network/auth attempt has its own finite profile timeout. The human decision has no network deadline but remains caller-cancellable; the synchronous UI prompt itself may still require dismissal. Existing known hosts use one connection. No accept-all mode, saved-IP fallback or DNS-budget change.

External executable validation rejects UNC, mixed slash, device-namespace and root-relative paths lexically before path resolution and existence probes; file URI forms are rejected too. Validation runs both before persistence and at launch/availability boundaries, including before RDP's system-path override. Tests inject throwing filesystem/path-resolution delegates and assert zero calls for rejected profiles.

The argument editor ignores whitespace-only lines, including trailing newlines. Nonempty argument text retains its spaces as one structured argument; stored empty/whitespace-only arguments are rejected. {port} in arguments must have an explicit or type-default port before saving. Network identity substitutions reject controls, option-like values, malformed DNS labels and ambiguous/invalid IPv4 octets. Invalid hostnames do not silently select a saved IP. Custom profiles execute explicitly trusted local programs; argument boundaries and identity validation are not a sandbox, and the selected executable owns argument semantics. No approval database, signature policy or dependency changes. Milestone F remains unimplemented.
